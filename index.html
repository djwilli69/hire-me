Case Study

Oil & Gas Well-Tracker Application

Built with Kiro · for my own business, J&T Cook Corporation
ReactSupabase / Postgres PythonVercel AI spec-driven

The problem. Working-interest oil & gas income arrives as a mess of operator statements, checks, and bank activity. I needed one place to see what I'd invested in each well, what had come back, whether it had paid out, and what it all meant at tax time.

What I built. A full-stack web app: dashboard with company-wide totals and a cash-flow timeline, per-well tracking, Python scripts that ingest operator PDF statements, bank-statement reconciliation, document management, and tax reporting — all behind magic-link auth with row-level security. Deployed to production on Vercel + Supabase.

Screenshots use sanitized sample data — the same public demo data as the GitHub repo.
What I did
  • Defined the vision, data model, and every feature requirement
  • Wrote the steering docs & conventions that guided the AI
  • Made the architecture calls (Supabase, auth model, access control)
  • Tested each feature against real statements and debugged until correct
  • Deployed and now run it in production for my business
What Kiro (AI) did
  • Generated the React components and Python parsers from my specs
  • Wrote first-pass SQL schema & migrations to my requirements
  • Produced boilerplate and wiring I reviewed and corrected
  • Iterated on fixes as I found issues in testing

The public repo is a sanitized copy with sample data. It includes the steering docs and decision logs — a direct look at how I direct AI and make design calls.
